# Agent friction log

Where agents complain. Tooling that fights back, conventions that read one way and
behave another, traps that cost time to rediscover — those go here. Bugs in product
code do not; they belong in the task report. Newest at top, entries at most three
lines, format:

`- [YYYY-MM-DD] <complaint>. <what it cost / how it was found>. <fix, if obvious>.`

- [2026-08-27] `.gitignore` ignores `/docs/*` with per-directory exceptions (`!/docs/specs/`, `!/docs/design/`), so any new top-level doc — this file included — is silently untracked and a `git add` looks like it worked. Found because `git status` never showed the new file. Needs `!/docs/AGENT_FRICTION.md`; better, invert the rule to ignore only what is actually local.
- [2026-08-27] No cross-process notification when another process advances a document head. `AuthoredDocuments` (`src-tauri/src/services/authored_documents.rs`) makes correctness come from the SQLite head CAS, so a second process only learns it was behind by *losing* a write it already did the work for. A head-change channel (or a bus event on commit) would turn a lost CAS into a refresh.
- [2026-08-27] `bin/luma-mcp` builds services with a bare `Arc::new(boot(...))` (line 677) while the turn loop needs `AppServices::into_shared()` to attach its back-reference. The harness hit this as a silent 100% failure of `agent_turn_start` — the error only exists because someone added it (`agent/host.rs`). Fix landed: `into_shared` returns a `SharedServices` newtype and is its only constructor, so a bare `Arc::new` no longer typechecks anywhere the turn loop is reachable.
- [2026-08-27] Bun hands child processes `RLIMIT_NOFILE = i64::MAX`, and loky's fork path closes fds in a loop bounded by it. Surfaced as the Python worker "hanging" with no error; the clamp now lives at `src-tauri/python/luma_exec/worker.py:111` before any heavy import. Anything else we spawn from Bun inherits the same limit.
- [2026-08-27] `resources/` is located three different ways by three subsystems — `services/fixtures.rs` (cwd `../resources` + `_up_/` bundle), `agent/skills.rs` (repo join + two `_up_` candidates), `headless_host.rs`/`run_goldens.rs` (repo-root join). Each new binary re-invents the search and one of them is always wrong first try. One `resources_root()` in the crate, everyone calls it.
- [2026-08-27] Headless gpui virtualizes time: `background_executor().timer()` never fires, because nothing advances `TestDispatcher`'s clock. Any UI debounce built on a gpui timer hangs forever under `cargo test` while working in pixel mode and production. Wait on the library's Tokio runtime instead (`Library::debounce`).
- [2026-08-27] Focus path in gpui is computed from the *rendered* frame, so a `FocusHandle` whose element stopped rendering still reports `is_focused == true` while its dispatch path is empty and keys fall to a context-less root. Cost a debugging session on a dialog morph that silently went deaf. Test liveness with `contains_focused`, never `is_focused`.
- [2026-08-27] `git stash` is process-global, so concurrent agents in one checkout share a stack; a worktree agent's `stash@{0}` was nearly popped by another agent. Use a worktree or a named branch commit — never bare `stash`/`stash pop` while anyone else is in the tree.
- [2026-08-27] Cargo must be invoked with cwd `gpui/` — rustup picks the toolchain from the working directory, not the manifest, so `--manifest-path gpui/...` from the repo root runs the default 1.90 instead of the pinned 1.97.1 and dies inside sqlx. Costs one confusing compile error per new agent. `gpui/BUILD.md` should say it in the first command block.
- [2026-08-27] `gpui/crates/agent/tests/support/chat.rs:298` keys the fixture database on the *process* id, so every `chat` test in a run shares one SQLite file and they collide with "database is locked". Found by running the suite unfiltered. Key it per test (pattern name is already unique) instead of requiring `--test-threads=1`.
- [2026-08-27] Editing a migration file after any machine has run it breaks every launch — sqlx checksums each version. The warning existed only as a comment inside two migration files; AGENTS.md, which is what an agent actually reads first, said nothing. Fix landed: AGENTS.md now has a Migrations section saying so.
- [2026-08-27] `docs/specs/ipc-manifest.{json,md}` regenerate-then-fail-once: `dispatch::manifest::check` writes the new files and *then* reports a mismatch, so the first run after any command change is always red and the tree is always dirty. With two agents in one checkout it flip-flops. Also, per-command prose and the whole `events` block are hand-written inside an otherwise generated file, carried across by name — an easy thing to clobber.
- [2026-08-27] A filtered `cargo test --lib <filter>` still runs ts-rs exports, and rewrites `src/bindings/schema.ts` with only the types the filtered tests touched — `bun run build` then fails on missing types until someone runs the full suite. Cost a confusing typecheck failure with no related diff. Documented in AGENTS.md; the real fix — gating binding export behind a feature or env var so partial runs can't half-write the file — is still open.
