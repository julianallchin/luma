Orientation:
- Inspect the branch relevant to the question. `luma.catalog()` is available when you need the full inventory, but do not dump it by default.
- In a graph score, `edit = luma.track.edit()` captures the document and revision. Create a one-node effect with `graph = edit.graph(node="chase")`, then `edit.add_clip(graph, beats=(32, 48), selection="front_wash", inputs={"width": .4})`. Use `bars=(1, 5)` or `seconds=(start, end)` when appropriate; all ranges are half-open. Beats are zero-based from the musical origin, bars one-based. `edit.update_clip(clip, inputs={...})` changes overrides; a `None` override restores the graph default. `edit.remove_clip(clip)` deletes it. `subset=` accepts a fraction, head count or `"all"`.
- Compose custom graphs with `graph = edit.graph()`, `node = graph.node(definition_id, **inputs)`, connections through `node.output(port)`, `graph.expose(node, input)` for clip controls, and `graph.output(final.output(port))` for the result. Node definitions are shared by clips; `edit.make_independent(clip)` copies local dependencies. Built-ins are read-only. Discover with `luma.track.nodes(search)` and `luma.track.definition(id)`; follow definition references to inspect subgraphs. `edit.source()` is the canonical score.luma JSON; `edit.replace_source(source)` stages it. Native editing, Python and model-authored JSON use one validator.
- Verify with `edit.diff()`, `edit.check()` and `view = edit.window(...)`. `view.timeline()` plots clips; `view.output.heatmap()` renders the actual candidate. `edit.apply()` commits and advances `luma.track`. In a child workspace it advances only the detached score, which a supervisor later merges. Opening a new edit after a conflict captures the current score.
- If the bound score still has `luma.patterns` rather than `luma.nodes`, it awaits manual migration: its legacy `edit.add_clip(pattern_id, ..., args={...})` uses the published pattern schemas. Do not pass old pattern IDs as new graph definitions.
- `luma.audio` is audio signal (mix, stems). `luma.features` is what was derived from audio (beats, downbeats, drum onsets, bar classifications, chords, waveform bands). Neither is a fallback for the other: pick the branch that matches the question.
- Tensors expose `.values` (numpy), `.shape`, `.axes`, `.times_s`, `.unit`, `.provenance`. Keyed families are dict-style: `luma.features.drum_onsets["kick"]`, `luma.audio.stems["drums"]`.
- `luma.venue` is the room: fixtures, `pieces` (the set design — booth, truss, speakers — each with a `kind` and a world position), groups, positions, `uv`. `luma.venue.render(view="front", t=0.0, width=960, height=540)` renders the actual stage at that moment and returns it to you as an image (also on disk at `.path`). `view` is one of `luma.venue.views`: front, audience, overhead, quarter_left, quarter_right, dj. The room is drawn under the editor's work light, so you can read both where the hardware is and what the score is doing to it. Pass `highlight="<selection expression>"` to light only the heads that expression resolves to (open white, everything else dark, the score at `t` not drawn) — the way to see what a selection actually covers.
- `luma.graph.run.views` holds the latest graph run's view-node output when a graph run is in scope. All times are absolute track seconds.
- Images are collected for you, never emitted by hand: every matplotlib figure still open at the end of the cell and every `luma.venue.render(...)` made during it comes back as an image. There is no `display()` — this is a plain Python process, not IPython.
