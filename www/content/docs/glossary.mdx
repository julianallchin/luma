This page defines the terms that the Luma code and documentation use.

## Data Overview

```
Library                                  Venue
|-- Tracks                               |-- Fixtures (universe, address, mode, position)
|   |-- Beat grid                        |-- Groups
|   |-- Stems (drums, bass, vocals,      |-- Stage pieces
|   |   other)                           '-- Members
|   |-- Roots (chord analysis)
|   |-- Drum onsets
|   '-- Bar classifications, genres
'-- Scores (one track + one venue)
    '-- Clips (form, start, duration, z index, blend mode, selection, inputs, seed)
```

## Venue

A physical room. A venue holds its fixtures, their DMX addresses, their positions, its stage pieces and its groups. A venue also records its environment (indoor or outdoor) and its haze.

## Fixture

One light that is patched into a venue. A fixture has a fixture definition, a mode, a DMX universe, a start address, a position and a rotation. Positions use a Z-up, right-handed coordinate system in metres.

## Head

One part of a fixture that Luma controls on its own. A pixel bar with 12 cells has 12 heads. Output state is keyed by `fixture-id` or `fixture-id:head-index`.

## DMX Universe

A set of 512 DMX channels. A venue can use more than one universe.

## Group

A named set of fixtures in one venue. A score selects fixtures by group name, not by fixture id. Group names are snake_case. They must match `[a-z][a-z0-9_]*` and cannot be `all`. See [Groups](/docs/user-guide/groups-and-tags).

## Selection Expression

A query over group names. It uses `&` (and), `|` (or), `^` (either side, chosen at random when both match), `~` (not), `>` (fallback) and parentheses. An empty expression or `all` selects every fixture.

## Track

An audio file in the library, with its analysis: beat grid, stems, chord roots, drum onsets, bar classifications and genres.

## Score

The light show for one track in one venue. A score is stored as rows: one `scores` row and one `clips` row per clip. A track can have many scores.

## Clip

One placement of a form on a score's timeline. A clip has a start and a duration in beats, a z index, a blend mode, a selection expression, input values and a seed.

## Graph Definition

A node graph with named inputs and outputs. A definition is either a primitive (a kernel in Rust) or a graph of other definitions. The standard library holds the built-in definitions. A clip plays one of its forms.

## Standard Library

The built-in definitions from `luma_patterns::standard_library()`. See the [node reference](/docs/node-reference).

## Output (Apply)

The terminal node of a lighting graph. Its catalog id is `output` and its display name is **Apply**. It has optional inputs for color, pan, tilt, strobe and movement speed. An input that is not wired leaves that capability unchanged.

## Signal

The value that flows on a wire. A signal is a three-dimensional array with a unit and a channel layout. The units are number, beats, proportion (0–1), position, degrees and seconds. The channel layouts are one value, RGB, pan/tilt and a vector of N components.

## Rate

Each port is `fixed` or `frame`. A fixed value does not change during the clip. A frame value can change on every frame. A frame-rate wire cannot connect to a fixed input.

## Blend Mode

How a clip combines with the clips below it. There are nine modes. See the [blend mode table](/docs/architecture/compositor#blend-modes).

## PrimitiveState

The output of one head at one moment: dimmer (0–1), color (RGB, 0–1), strobe (0–1), position (pan and tilt in degrees) and speed (0 or 1).

## UniverseState

The `PrimitiveState` of every head at one moment. It is not a DMX universe.
