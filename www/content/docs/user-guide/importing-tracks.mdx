# Import Tracks

Luma must analyze a track before a graph can react to it. You must be signed in to import tracks.

## Add Songs to a Venue

The song list (⌘P) shows the songs of the open venue. **Add songs** in its head opens a dialog of every track already in your library. Pick one to add it to the venue.

## Sources

**Import tracks**, in the same dialog, brings in new tracks from:

- **Engine DJ.** Playlists from an Engine DJ database.
- **Rekordbox.** Playlists and crates from Rekordbox.
- **Files…** Audio files from this computer.
- **Folder…** Every audio file in a folder.

A DJ library opens as a list you can filter and select from. You can play a row to hear it, and see its cover, before you import it. A track longer than 10 minutes is refused.

Import adds the tracks to the library and to the venue first. Analysis runs after that, in the background. The dialog shows the import song by song, and the status bar shows it too.

## Analysis

Analysis is a set of preprocessors. Each preprocessor reads some inputs and writes one result. Luma runs a preprocessor when its inputs are ready.

| Preprocessor | Reads | Writes | Model |
|--------------|-------|--------|-------|
| `beat_grid` | Audio | Beat grid: beats, downbeats, BPM | beat_this |
| `stems` | Audio | Four stems: drums, bass, vocals, other | Demucs `htdemucs` |
| `mert` | Full mix and drum stem | Cached MERT features | MERT-v1-95M |
| `roots` | Bass and other stems | Chord roots | consonance-ACE |
| `n2n` | MERT features | Drum onsets: kick, snare, hi-hat, cymbal | n2n |
| `classifier` | Beat grid and MERT features | Per-bar tags and intensity | Bar window classifier |
| `genre` | Audio and beat grid | Per-bar genre styles | Discogs-EffNet |

Luma does not ship the Discogs-EffNet weights. The `genre` preprocessor downloads them on first use.

Luma also makes waveform data for the timeline.

### Order

`beat_grid` and `stems` read only the audio, so they run at the same time. `roots` waits for the stems. `n2n` waits for the MERT features. `classifier` waits for the beat grid and the MERT features. If a preprocessor fails, Luma skips the preprocessors that need its result. It tries the failed track again later, with a longer wait each time, up to 24 hours.

A preprocessor has a version. When the version increases, Luma runs it again on every track.

## What a Graph Can Read

Clips are placed in beats, so every clip graph follows the beat grid: a `time` node counts in beats. An `audio` node reads the energy of one frequency band of the full mix, 0–1 over the whole track.

## Analysis Environment

The preprocessors run Python workers. Luma sets up a Python 3.12 environment in the background.

On a computer with an NVIDIA GPU, Luma reads the driver's CUDA version and the GPU's compute capability from `nvidia-smi`. It then installs a matching PyTorch CUDA build: `cu128`, `cu126`, `cu124` or `cu118`. If no build matches, or the CUDA install fails, Luma installs the CPU build.

Luma looks for a bundled ffmpeg first. If it does not find one, it uses the ffmpeg on the system `PATH`.
