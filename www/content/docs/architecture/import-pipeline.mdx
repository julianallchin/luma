The import pipeline adds tracks to the library, analyzes their audio and
connects to DJ equipment.

## Track import

File: `backend/src/services/tracks.rs`

Every import goes through `Importer::import`. It inserts the requested
tracks one by one, reports progress, and hands the new rows to background
analysis. An identity change mid-batch rolls back every row it inserted.
A request is one of two kinds:

| Request | Behavior |
|---------|----------|
| `ImportRequest::File` | Reads tags with `lofty` and extracts album art. A song with no title tag is named for its file. |
| `ImportRequest::Library` | Imports an Engine DJ or rekordbox row with the library's metadata. |

- Every import converts the audio to Ogg Opus in the managed tracks directory
  (`audio::stored`). That is the only copy Luma keeps: sync uploads the same
  bytes, and a DJ library can move or be unplugged afterwards. The source's
  extension is not trusted; ffmpeg reads what the file contains.
- Every import rejects tracks longer than 10 minutes, measured on the
  converted audio. Conversion stops just past the limit.
- Every path computes a content hash of the source file, and stops before
  converting when the library already has that song.
- Songs imported before this are converted by the media sync pass
  (`sync/legacy_audio.rs`, which says when it can be deleted).
- The DJ paths match an existing track by source id first, then by content
  hash.

Audio is decoded once, with ffmpeg, to stereo at
48 kHz (`audio::SAMPLE_RATE`). Every `.pcm` cache is at that rate; a cache at
any other rate is re-decoded. Playback converts to the output device's rate in
its output stream, never on disk.

## Background analysis

`run_background_analysis` runs after import:

1. It fills missing metadata from the file tags.
2. It runs waveform generation and the preprocessing DAG at the same time.

Waveforms are computed in Rust (`backend/src/services/waveforms.rs`).

## Preprocessing DAG

Files: `backend/src/preprocessing/`

Each preprocessor declares its inputs and its output. The scheduler sorts them
by dependency at startup. The registry is `registry.rs`.

| Preprocessor | Inputs | Output | Worker |
|--------------|--------|--------|--------|
| `beat_grid` | Audio | Beat grid | `beat_worker.py` |
| `stems` | Audio | Stems | `audio_preprocessor.py` (demucs `htdemucs`) |
| `mert` | Audio, Stems | MERT features | `mert_worker.py` (MERT-95M) |
| `roots` | Stems | Chord roots | `ace_chord_sections_worker.py` (consonance-ACE) |
| `n2n` | Stems, MERT | Drum onsets | `n2n_worker.py` |
| `classifier` | Beat grid, MERT | Bar classifications | `classifier_worker.py` |
| `genre` | Audio, Beat grid | Genres | `genre_worker.py` (Discogs-EffNet, ONNX) |

- Preprocessors in the same layer run in parallel for one track.
- A semaphore limits how many tracks run at once. The limit is
  `(RAM in GB − 4) / 3`, clamped to 1–6.
- Each artifact row has a `processor_version`. A row with an older version runs
  again. A row downloaded by sync counts as complete.
- A beat grid is written once. A new analysis inserts a new `track_beats` row,
  and the newest row is the track's current grid. The other artifacts are a
  cache: one row per track (one per stem for stems), replaced when the
  preprocessor runs again.
- A failure is stored in the local `preprocessing_failures` table. The retry
  uses exponential backoff, up to 24 hours. Until then the preprocessor is
  skipped on that track, and so are the preprocessors that depend on its
  output, unless one of its inputs was rebuilt in the same run. Startup forgets
  the failures of an older version of a preprocessor, and those recorded before
  the Python environment was last reinstalled.
- A preprocessor that fails with the same error on three tracks in a row is
  skipped on the rest of the batch (an import, or the startup catch-up),
  because it is the preprocessor that is broken, not the tracks. The next
  batch tries it again.
- The scheduler emits `track-import-state` events during an import. Each
  analysed track is first `queued` with every stage it will report (each
  preprocessor plus `waveform`); each stage then starts and settles exactly
  once, as done, skipped or failed. The import's `complete` event follows only
  after both the preprocessors and the waveform branch have drained.

The bar classifier weights are bundled in the app. The genre model is
downloaded on first use into the models directory and checked against a pinned
checksum.

## Python environment

File: `backend/src/runtime/python.rs`

- Python 3.12 is required (`PY_MIN_VERSION` and `PY_MAX_VERSION_EXCLUSIVE`).
- The virtual environment is in `python-env` in the app cache directory.
- Requirements come from six files: the main `requirements.txt` and the files
  for consonance-ACE, MERT, n2n, the classifier and genre.
- A hash of the requirements and the PyTorch choice is stored in
  `.requirements.hash`. Install runs again only when the hash changes.

### PyTorch choice

1. On macOS, Luma installs the default PyPI wheel. It includes MPS on Apple
   Silicon.
2. Otherwise Luma runs `nvidia-smi` to read the driver CUDA version and the GPU
   compute capability. It picks the first matching row:

| Index | torch | torchvision | Minimum CUDA | Minimum compute capability |
|-------|-------|-------------|--------------|----------------------------|
| `cu128` | 2.8.0 | 0.23.0 | 12.8 | 7.5 |
| `cu126` | 2.8.0 | 0.23.0 | 12.6 | 5.0 |
| `cu124` | 2.6.0 | 0.21.0 | 12.4 | 5.0 |
| `cu118` | 2.6.0 | 0.21.0 | 11.8 | 3.5 |

3. With no match, or if the CUDA install fails, Luma installs the CPU wheel.

## StageLinQ

Files: `backend/crates/stagelinq/src/`

Luma has a Rust implementation of the Denon StageLinQ protocol.

| Component | File | Purpose |
|-----------|------|---------|
| Discovery | `discovery.rs` | UDP announcements on port 51337 |
| Device | `device.rs` | TCP connection to one device |
| Protocol | `protocol.rs` | Message encoding and decoding |
| State map | `services/state_map.rs` | Track and deck state |
| Beat info | `services/beat_info.rs` | Beat position and BPM |

Discovery opens one announce socket per network interface. Each socket is bound
to the interface address, so a broadcast leaves on the correct interface.
Interfaces are listed with the `if-addrs` crate.

## Pro DJ Link

Files: `backend/crates/prodjlink/src/`, `backend/src/perform/mod.rs`

The Pro DJ Link client binds UDP ports 50000, 50001 and 50002:

| Port | Data |
|------|------|
| 50000 | Keepalive announcements |
| 50001 | Precise position |
| 50002 | Player status |

`metadata.rs` fetches track metadata from players.
