title: Architecture Overview
description: Native desktop stack, shared backend, and repository organization
---

Luma is a native Rust desktop app built with GPUI. The UI owns windows, input,
and editing surfaces; the shared backend owns persistence, audio analysis,
pattern evaluation, agents, synchronization, and physical lighting output.
The documentation website in `www/` is a separate Next.js application.

## Tech Stack

- **Native UI**: GPUI, gpui-component, and Luma's reusable UI components.
- **Rendering**: wgpu, with a shared scene model and fixture kinematics.
- **Backend**: Rust, Tokio, SQLite through sqlx, symphonia for decoding, and CPAL for playback.
- **Analysis**: Python workers for beats, stems, chords, MERT features, classifications, and genres.
- **Networking**: Supabase synchronization, StageLinQ and Pro DJ Link telemetry, and Art-Net output.

## Data Architecture

Patterns and scores describe lighting independently of physical fixtures.
Selection expressions name groups; each venue maps those groups to its own rig.

The global library database remains `luma.db` in the platform app config directory:

- macOS: `~/Library/Application Support/com.luma.luma/luma.db`
- Linux: `~/.config/com.luma.luma/luma.db`
- Windows: `%APPDATA%\com.luma.luma\luma.db`

Venues are rows in this database, not separate project files. Authored documents
and immutable revisions share the library with tracks, groups, patterns, and
scores. Authentication state uses the separate `state.db` beside it.

## Repository Organization

```text
gpui/
  crates/app/       Native windows, editing surfaces, and desktop lifecycle
  crates/ui/        Reusable controls, themes, and embedded Nucleo icons
  crates/chat/      Agent conversation UI
  crates/md/        Markdown rendering
  crates/scene/     Shared scene model and spatial geometry
  crates/render/    wgpu renderer
  crates/agent/     Native automation and UI test harness
  crates/harness/   Component catalog
backend/
  src/models/      Shared Rust schemas
  src/database/    SQLite and remote database access
  src/services/    Domain operations and authored history
  src/dispatch/    Command table and handlers using AppServices
  src/eval/        Pattern and score evaluation
  src/preprocessing/  Audio-analysis scheduling
  src/agent_execution/  Python workspaces and tools
  crates/          Pattern engine, fixture kinematics, DJ protocols, MCP
  python/          Analysis workers
  migrations/      Append-only SQLite migrations
resources/         Fixture definitions, meshes, and bundled skills
supabase/          Remote database migrations
harness/           Renderer references and comparison tools
www/               Documentation website
```

The desktop and backend tools call the same `luma_lib::dispatch` handlers.
The native library owns its Tokio runtime; host events carry progress back to
GPUI. Desktop startup prepares Python in the background and enables physical
Art-Net output. Headless tests construct services without those side effects.

The Rust workspaces remain separate so native UI and backend tooling can retain
their own build profiles. See `gpui/BUILD.md` for build and test conventions.
