title: DMX Output Pipeline
description: Lighting state to DMX channel values, strobe handling, color wheels, and output over Art-Net and USB
---

The DMX pipeline converts lighting states into DMX values and sends them to
Art-Net nodes and USB DMX dongles.

## Lighting state

`PrimitiveState` (in `backend/src/models/universe.rs`) is the state of one
fixture or head at one time:

```rust
pub struct PrimitiveState {
    pub dimmer: f32,        // 0.0 - 1.0
    pub color: [f32; 3],    // linear Rec. 2020 [0.0 - 1.0], peak 1
    pub strobe: f32,        // 0.0 (off) - 1.0 (fastest)
    pub position: [f32; 2], // [PanDeg, TiltDeg]
    pub speed: f32,         // 0.0 (frozen) or 1.0 (fast) - binary
}
```

`UniverseState` maps an id to a `PrimitiveState`. The id is a fixture id, or a
fixture id and a head index: `fixture-id:0`.

## Channel mapping

File: `backend/src/fixtures/engine.rs`. The function `generate_dmx` writes one
512-byte buffer per universe.

| Channel type | Mapping |
|--------------|---------|
| Master dimmer | The brightness × 255, scaled by the Max Dimmer setting. On a color wheel fixture, the brightness is first multiplied by the color luminance. |
| Red, green, blue, white, amber, lime | The emitter level × 255. See [Color into emitters](#color-into-emitters). |
| Cyan, magenta, yellow | 255 × (1 − the level of the color it filters out) |
| Color wheel | The nearest wheel color. A black color holds the previous value. |
| Pan, tilt | Signed degrees centered on 0, mapped over the fixture's pan or tilt range to a 16-bit value. A coarse channel gets the high byte. A channel with "fine" in its preset gets the low byte. A NaN value holds the previous value. |
| Shutter | Controlled by the strobe rules below |
| Speed | Speed above 0.5 writes 0 (fastest). Otherwise it writes 255 (slowest). |

The engine does not invert pan or tilt. Pan and tilt go out as the evaluator
produced them.

The Max Dimmer setting is a percentage. Its default is 100.

### Multi-head fixtures

Channels inside a `<Head>` read the state of that head. A master dimmer reads
the fixture state. If there is no fixture state, channels fall back to head 0.

### Color into emitters

A head's color is linear Rec. 2020 (see
`backend/crates/patterns/src/color_space.rs`). `HeadColor::new` turns it into
the fixture's emitters once per head:

1. `Gamut::split` converts the color to the levels of red, green and blue
   emitters. Fixture definitions do not give emitter chromaticities, so the
   engine assumes sRGB primaries. If the emitters cannot make the color, the
   color moves toward the gray of the same OKLab lightness, with the same
   hue, until they can. Channels are never clipped one at a time.
2. The levels are normalized to a peak of 1. The brightness is the head's
   dimmer times that peak, at most 1.
3. A white, amber or lime emitter takes as much of the color as it can make.
   Red, green and blue make the rest. The engine assumes a D65 white, a 590 nm
   amber and a lime at CIE xy (0.40, 0.55).
4. A fixture with a master dimmer gets the brightness there. A fixture
   without one gets only the emitter levels: the brightness does not reach
   it.
5. A fixture with cyan, magenta and yellow and no red, green or blue has
   filters on a white lamp: each filter is 1 minus the level it passes.

A level is linear light: DMX 128 is half of the light of 255.

### Color wheels

`map_nearest_color_capability` compares the requested color, as linear sRGB
at a peak of 1, with the color of each wheel slot. The distance adds a saturation penalty. A gray request
therefore prefers a white slot over a saturated slot.

## Strobe

The engine picks one method per fixture per frame. It uses the first method
that the fixture supports:

1. Per-head shutter channels.
2. The master shutter channel, if all heads have the same strobe value.
3. A pulse on per-head dimmer channels.
4. A pulse on the master dimmer, if all heads agree.
5. A pulse on per-head color channels.
6. A pulse on the master color channels, if all heads agree.

Two strobe values agree when they differ by less than 1/256. A pulse is a
square wave. Its frequency is `strobe × 20` Hz.

When strobe is 0, the shutter writes its "Open" capability. If the channel has
no "Open" capability, it holds the previous value. When the engine pulses
another channel, the master shutter is set to "Open".

## Output

Files: `backend/src/output/` (`mod.rs`, `artnet.rs`, `usb.rs`).

The desktop host runs `run_output` in `backend/src/dispatch/services.rs`. Every
23 ms it samples the render engine at the audio playback time. `OutputHub`
turns the sample into 512-slot universes and publishes them as the latest
frame. When output stops, it publishes one empty frame.

Each transport is a driver with its own thread. A driver reads the newest frame
at its own pace and skips frames it missed. A slow or unplugged USB dongle
cannot delay the render loop or the network.

The `dmx_output_enabled` setting turns every driver on or off. While it is off,
no driver holds a socket or a device.

### Routes

The local-only `dmx_routes` table says where each universe goes. A row names a
device kind (`art-net` or `usb`), a device id, and a port on that device. A
universe can have several rows. A universe with no row is not sent.

Device ids are stable across restarts:

- An Art-Net node is identified by the MAC address in its ArtPollReply, or by
  its IP if it reports no MAC.
- A USB dongle is identified by `vid:pid:serial`. If it has no serial, the bus
  and port path replace the serial.

The patch page's Outputs panel lists devices with `list_output_devices` and
edits routes with `bind_route` and `unbind_route`.

## Art-Net

### ArtDmx packet

| Field | Value |
|-------|-------|
| ID | `Art-Net\0` |
| OpCode | `0x5000`, low byte first |
| Protocol version | 14 |
| Sequence | Increments once per frame |
| Physical | 0 |
| Port address | 15-bit Net/SubNet/Universe |
| Length | 512 |
| Data | 512 DMX values |

### Destinations

- A route's port is the node's own port address, from its ArtPollReply. It is
  not derived from the Luma universe number.
- Packets go to the node's IP from its latest reply. Before the first reply,
  they go to the address stored with the route.
- The `broadcast` device sends to `255.255.255.255:6454` and to the directed
  broadcast address of the local /24 network. A broadcast route uses the
  universe number as its port address.

### Discovery

While output is on, the driver sends ArtPoll (`0x2000`) every 3 seconds. It
sends to the same two broadcast addresses. It reads ArtPollReply (`0x2100`)
packets to list nodes and their output ports. A node that does not reply for
10 seconds is removed from the list.

## USB dongles

The USB driver scans the bus every second. Each supported device gets its own
thread. The thread sends the start-up packets, then one frame per output every
25 ms. An output with no route gets zeros. When output turns off or the device
thread stops, it sends three blackout frames.

Supported devices:

| Device | USB ID | Outputs |
|--------|--------|---------|
| SoundSwitch Micro DMX Interface | `15e4:0053`, `15e4:005a` | 1 |
| SoundSwitch Control One | `15e4:0054` | 2 |

The SoundSwitch protocol comes from the Apache-2.0
[QLC+ SoundSwitch integration](https://github.com/jloops412/qlcplus-soundswitch-integration).
Everything goes to bulk endpoint `0x01`. A DMX frame is `sTRt 01 00 02 02`,
the output index, `00`, then 512 values.

On Linux, the user needs permission to open the device. Install
`resources/linux/70-luma-dmx.rules` (see `gpui/BUILD.md`). Without it, the
device appears in the Outputs panel with a permission message.
