The selection system turns a group expression into a list of fixture heads.
It is the mechanism that lets a score play in different venues.

## Selection expressions

File: `backend/src/services/groups.rs`

An expression combines group names with operators. A name matches the fixtures
in the group with that snake_case name in the current venue. The keyword `all`
matches every fixture.

```
all                          -- every fixture in the venue
front_wash                   -- fixtures in the front_wash group
front_wash & left_truss      -- fixtures in both groups
left_truss | right_truss     -- fixtures in either group
floor_ring & ~dj_booth       -- floor_ring fixtures not in dj_booth
strobes > front_wash         -- strobes; front_wash if strobes matches nothing
```

### Operators

The parser gives these operators precedence from lowest to highest:

| Operator | Name | Meaning |
|----------|------|---------|
| `>` | Fallback | Use the left side. If it matches nothing, use the right side. |
| `\|` | OR | Either side matches |
| `^` | XOR | One side. If both sides match, the seed picks one at random |
| `&` | AND | Both sides match |
| `~` | NOT | Negates the next term |
| `( )` | Grouping | Changes the order |

## Whole groups

A selection is only a group expression (`Selection` in
`backend/crates/patterns/src/selection.rs`). It always means every fixture the
expression matches. For a random share of heads, use a `shuffle` node read by an
order `space` and a curve, as the Sparkle preset does. For specific heads, make a group for them.

A stored selection that still has a `subset` key from an older version loads as
the whole group. The key is dropped when the selection is saved.

## Cells

A graph does not reference fixtures. The host resolves the selection of each
clip and gives the engine a list of `Cell` values
(`backend/crates/patterns/src/mapping.rs`):

| Field | Meaning |
|-------|---------|
| `id` | Head identity |
| `group` | Group name |
| `world` | Position in venue space: X stage right, Y upstage, Z up |
| `uvz` | Position in stage space |

`Cell::stage_coordinates` converts venue space to stage space: U right, V
downstage, Z up.

## Positions in a clip graph

A `space` node turns the cells into a coordinate per head. Its `kind` is
`line` (along a direction), `order` (sorted along a direction), `radial`
(distance from a centre) or `angle` (turns around a centre). Its ruler runs
0–1 across the clip's selection. A `split` node makes each fixture or each
group its own span, and a `mirror` node folds the heads across a plane. A
negative direction runs the other way. See the
[node reference](/docs/node-reference/coordinates#space).

## Rig UV

File: `backend/src/node_graph/geometry.rs`, function `rig_uv`.

`rig_uv` gives each position a `(u, v)` pair from 0 to 1 over the selection:

- **`u`** is the first principal component of the horizontal (XY) spread. Its
  sign is set so that its largest world component is positive. With no
  horizontal spread, `u` is the normalized index.
- **`v`** is world height (Z) over the selection. With no height spread, `v`
  is 0.5.

The agent venue tools use `rig_uv`
(`backend/src/agent_execution/bindings/providers/venue.rs`).
