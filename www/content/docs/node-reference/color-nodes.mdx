# Color Nodes

Color is an RGB signal. Its fixture and time dimensions broadcast like other
signals. Set a constant color or gradient in the inspector, or connect a named
Input to share and expose that control.

Palettes retain up to 64 stops. A single stop is a constant color; an empty
palette samples as black. The inspector shows “No colors” for empty values and
lets you add a color or remove the last one. Empty clip overrides remain distinct
from an inherited graph default.

`palette_fallback` takes a `gradient` and a `fallback`, returning the first when
it contains any colors and the fallback otherwise. An explicit black color counts
as a color. Saved harmonic palettes use this operation to preserve their original
rainbow fallback while sharing the same Input with other consumers.

## Sample gradient

`sample_gradient` samples a structured gradient at
`position`. A position of 0 selects the start and 1 the end; positions outside
that range hold the nearest endpoint. Interpolation between stops uses OKLab.
The `color` output carries RGB; `opacity` samples the stop opacity as a separate
scalar signal. Both preserve the position signal's fixture and time dimensions.
Connect opacity to Output's Dimmer, or multiply it by an independent intensity
signal. Existing color-only connections keep their brightness behavior.

Connect mapped position and travel phase through Add and Fraction to make a
traveling palette ribbon. Its intensity can come from an independent Envelope,
Chase or other numerical signal.

## Mix palette

`mix_palette` takes a `gradient` and a vector of `weights`. Each channel weights
one palette color; the result is their sum. Multiple fixtures and times can have
different weights. The outputs are `color` (RGB) and `opacity` (a separate scalar
signal). Neither output is clipped by the mixer.

`perceptual` selects OKLab mixing. In this mode, when the weight count matches
the stop count, weights refer directly to the authored stops. Otherwise, colors
are sampled evenly across the gradient. `vibrance` controls chroma correction
in perceptual mode and defaults to 0.6. Ordinary RGB mixing is the default and
always uses evenly sampled colors.

## HSV

`hsv` constructs RGB from `hue` in turns, `saturation` and `value`. Saturation and
value default to 1. Hue wraps in either direction; 0 and 1 are red, one third is
green, and two thirds is blue. The resulting RGB is clipped to 0–1.

## Rotate hue

`rotate_hue` takes `color` and `turns`, producing `color`. Zero leaves the hue
unchanged; one third rotates red to green. Negative values rotate the other way.
Both inputs can vary across fixtures and time.

Rotation preserves the minimum and maximum RGB channels. It therefore preserves
HSL lightness and HSV value/saturation. Gray stays gray. Numerical values outside
0–1 retain their headroom until a downstream operation or Output bounds them.

## Pitch-driven hue rotation

Use `core/channel_argmax` (Strongest channel) to find the index of the greatest
pitch weight, Divide by 12, then connect that signal to Rotate hue's `turns`.
Strongest channel accepts any channel count, returns a zero-based index per
fixture and time, and chooses the first index on ties. Multiply the rotation
signal to control its strength.

Saved Spectral Shift nodes migrate to this composition. They retain the old
first-selected-head behavior and ignore the old Strength setting, which never
affected playback. New compositions can operate independently on every head.

## Output

Connect color to Output's Color port. With an explicit Dimmer connection, color
and intensity remain independent. With Color alone, Output extracts brightness
from RGB. Other capabilities, including movement, accept their own signals.
